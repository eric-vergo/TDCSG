They were compared with `theorem1-converse.md` ([T1]) and `boundary-contact.md` ([BC]).

**Overall verdict.** The build is clean, and the axioms are only `propext`, `Classical.choice` and `Quot.sound`. ## 3. The definitions, unfolded to Mathlib

| Lean | Literal meaning |
|---|---|
| `leftCenter`, `rightCenter` | `-1 : ℂ` and `1 : ℂ` |
| `leftDisk r`, `rightDisk r` | `Metric.closedBall (∓1) r = {z : dist z (∓1) ≤ r}`, the closed disk. For `r < 0` it is empty, and for `r = 0` it is the centre alone. |
| `rotation n c z` | `c + exp (-(2πi / (n:ℂ))) * (z - c)`, a rotation by angle **−2π/n** (clockwise), matching ζ = e^{−2πi/n} in [T1] Definition 1.2 and [BC] §1. I confirmed the direction by proving `permA 4 1 0 = -1 - i`. For `n = 0`, Lean evaluates `x / 0` as `0`, so this is the identity (documented in `Group.lean`). For `n = 1` it is a rotation by 2π, also the identity, as in the mathematics. |
| `diskRotation n c r z` | `rotation n c z` if `z ∈ closedBall c r`, and `z` otherwise (classical `if`). |
| `diskPerm n c r` | `Equiv.ofBijective (diskRotation n c r) _`, the same function packaged as a permutation. Bijectivity is proved for `n ≠ 0` from `f^[n] = id`, and for `n = 0` the function is `id`. |
| `permA n r`, `permB n r` | `diskPerm n (-1) r` and `diskPerm n 1 r` |
| `GG n₁ n₂ r₁ r₂` | `Subgroup.closure {permA n₁ r₁, permB n₂ r₂} : Subgroup (Equiv.Perm ℂ)`, the subgroup of Sym(ℂ) generated by a and b, matching [T1] Definition 1.3 and [BC] Definition 1.1. Composition is `(g*h) z = g (h z)`, the convention [T1] uses. |
| `orbit n₁ n₂ r₁ r₂ p` | `{y | ∃ g ∈ GG …, g p = y}`, the group orbit. It equals `MulAction.orbit (GG …) p` (proved: `mulAction_orbit_eq`). |
| `diskUnion r₁ r₂` | `leftDisk r₁ ∪ rightDisk r₂` (U in [T1]) |
| `TouchesBoundary S r` | `∃ y ∈ S, dist y (-1) = r ∨ dist y 1 = r`, alternative (B) of [BC] Theorem 5.1 |
| `AccumulatesInside S r` | (i) for every ε > 0, the set `{y ∈ S | ∃ c ∈ {−1, 1}, r − ε < dist y c < r}` is infinite; **and** (ii) for some `c ∈ {−1, 1}` and some `y` with `dist y c = r`, `y` is an accumulation point (`AccPt`, i.e. `ClusterPt y (𝓝[≠] y ⊓ 𝓟 (S ∩ ball c r))`) of `S ∩ ball c r`. This is exactly alternative (A) of [BC] Theorem 5.1(2), both sentences: in a metric space, "a limit of distinct points of the open disk" is the same as an accumulation point of the set. |
| `preserving S` | the subgroup of permutations g with g(S) ⊆ S and g⁻¹(S) ⊆ S, an auxiliary notion not used in any statement |

**Degeneracy check.**
- The disks are genuine closed disks for `r > 0`.
- The generators are not the identity for `n ≥ 2`, `r > 0`. Their order is exactly `n` (`orderOf_diskPerm`, and my own check below).
- The group is the actual generated subgroup, and the orbit is the actual group orbit.
- Finiteness is stated for the right object: `Finite ↥(GG n₁ n₂ r₁ r₂)`, the subgroup as a type.
- The only junk values are at `n = 0` (identity) and `r ≤ 0` (identity generators). Neither can trivialize a stated result:
  - `n = 0` is excluded from the finiteness theorems by the lcm hypothesis, since `Nat.lcm 0 k = 0 ∉ {1, 2, 3, 4, 6}` (checked by `decide`).
  - The monotonicity and boundary statements are true for every `n`, so allowing `n = 0` only generalizes them.
  - `r ≤ 0` forces every orbit to be `{p}` (`orbit_of_nonpos`). So the "infinite orbit" hypotheses of the boundary theorems force `r₀ > 0` automatically.
- `Real.pi` and `Complex.exp` are the genuine Mathlib functions.

## 4. Statement-by-statement comparison

| Lean name (`TDCSG.Statements.`) | Literal meaning | Written counterpart | Verdict |
|---|---|---|---|
| `finite_of_encard_orbit_le` | Let G be a finitely generated group acting faithfully on X. If every orbit has `encard ≤ N`, then G is finite. | [T1] Prop. 4.2 and [BC] Prop. 3.3, "if" direction | **Faithful**, but weaker: there is no explicit bound on \|G\|, and the "only if" direction is in `Monotonicity.encard_orbit_le_card` but not in `Statements`. "Group of bijections" corresponds to `FaithfulSMul`. |
| `orbit_mono` | For all n₁, n₂, r₁ ≤ r₁′, r₂ ≤ r₂′ and p: O_{(r₁,r₂)}(p) ⊆ O_{(r₁′,r₂′)}(p) | [BC] Thm 3.1 (coordinatewise pairs) | **Faithful**. It also covers all n (including 0) and all real radii. |
| `finite_GG_of_le` | Under the same order hypotheses, if GG at (r₁′, r₂′) is finite, then GG at (r₁, r₂) is finite. | [BC] Thm 3.4 | **Faithful** |
| `lcm_mem_iff` | lcm(n₁, n₂) ∈ {1, 2, 3, 4, 6} ⇔ (n₁ ∣ 4 ∧ n₂ ∣ 4) ∨ (n₁ ∣ 6 ∧ n₂ ∣ 6), for all naturals (0 ∣ 4 is false, so 0 is excluded on both sides) | [T1] Cor. 5.2, first sentence | **Faithful** |
| `exists_encard_orbit_le` | If lcm(n₁, n₂) ∈ {1, 2, 3, 4, 6}, then for all real r₁, r₂ there is an N with every orbit of `encard ≤ N`. | [T1] Thm 5.1(1) | **Weaker in form**: N is existential, not the explicit m·#{t ∈ ℤ[ω] : \|t\| ≤ 2R}. The proof's N is `#(S) + 1`, where S is a finite subset of (Gaussian or Eisenstein lattice)², not the paper's number. It is stronger in allowing r ≤ 0. The mathematical content (a uniform bound) is intact. |
| `finite_GG` | If lcm(n₁, n₂) ∈ {1, 2, 3, 4, 6}, then `Finite (GG n₁ n₂ r₁ r₂)` for all real r₁, r₂. | [T1] Thm 5.1(2) and Cor. 5.2 | **Faithful** apart from the explicit bound on \|G\|, which is not formalized. It covers unequal radii and unequal orders. The single-n case GG_n(r), n ∈ {1, 2, 3, 4, 6}, is the instance n₁ = n₂ = n. |
| `exists_orbit_eq_of_finite` | If the orbit at the common radius r₀ is finite, there is a δ > 0 with O_r(p) = O_{r₀}(p) for all r ∈ [r₀, r₀ + δ). | [BC] Thm 4.1 | **Faithful**, with δ existential rather than the explicit minimum. The theorem holds for closed disks only, which is what the written statement says. |
| `infinite_orbit_radii` | {r ∈ ℝ : O_r(p) infinite} is ∅, or equals `Ici r₀` = [r₀, ∞) for some r₀ > 0. | [BC] Cor. 4.2 | **Slightly weaker**: it gives r₀ > 0, not r*(p) ≥ 1. The written proof of r* ≥ 1 uses the tangent case of [T1] Prop. 7.1(2), which is not formalized. Taking the set over all reals rather than r > 0 makes no difference, since an infinite orbit forces r > 0. |
| `boundary_depth` | Suppose O_{r₀}(p) is infinite and O_r(p) is finite for all r < r₀. Then for every ε > 0 there are y ∈ O_{r₀}(p) and c ∈ {−1, 1} with r₀ − ε < dist y c ≤ r₀. | [BC] Thm 5.1(1): the infimum of the inner depths is 0 | **Faithful**. "inf d_k(y) = 0 over y ∈ D_k(r₀)" means exactly that, for all ε, some depth lies in [0, ε). The hypothesis "for all r < r₀" is equivalent to the written "for a sequence r ↑ r₀" by monotonicity, as [BC] itself notes. |
| `touchesBoundary_or_accumulatesInside` | Same hypotheses ⇒ (B) ∨ (A), with (A) = `AccumulatesInside` as unfolded in §3 | [BC] Thm 5.1(2) | **Faithful**. The quantifiers are in the right order (∀ ε, the set is infinite), the inequalities are strict inside, the circle is `dist = r₀`, the disk for the accumulation point is open (`ball`), and the accumulation point lies on the circle. |
| `of_not_touchesBoundary` | Same hypotheses plus ¬(B) ⇒ (A) ∧ O_{r₀}(p) = ⋃_{r<r₀} O_r(p) ∧ ∀ N ∃ r₁ < r₀ ∀ r ∈ [r₁, r₀), N < \|O_r(p)\| | [BC] Thm 5.1(3) | **Faithful**. The last conjunct is exactly \|O_r(p)\| → ∞ as r ↑ r₀. |
| `card_GG_of_add_lt_two` | If n₁, n₂ ≠ 0, r₁, r₂ > 0 and r₁ + r₂ < 2, then `Nat.card (GG …) = n₁ * n₂`. | [T1] Prop. 7.1(1) | **Weaker than its docstring**: the statement gives the order n₁·n₂ only, while the docstring says "the group is C_{n₁} × C_{n₂}". The isomorphism is built inside the proof (`MonoidHom.noncommCoprod`, injective, with range GG) but is not exported. As a sanity check it does its job. Since `Nat.card` is 0 for infinite types, the equation also forces GG to be finite, so it is not vacuous. |

**The critical radius in the boundary theorems.** Their hypotheses are "O_{r₀}(p) is infinite and O_r(p) is finite for r < r₀". By `infinite_orbit_radii`, this says exactly that r₀ = r*(p), which is the setting of the written Theorem 5.1. The quantifier order is correct: p and r₀ are fixed first, and the conclusion is about that single orbit. "Infinite" means `Set.Infinite` and "finite" means `Set.Finite`, both of the orbit sets, which is correct.

**Is any hypothesis unsatisfiable?** The boundary theorems need some p and r₀ with an infinite orbit, which the paper establishes for n = 5. Nothing in Lean shows that such parameters exist, so inside Lean their non-vacuity rests on the definitions being correct (checked above and in §5) and on the paper. I did not try to prove an infinite orbit in Lean. The hypothesis of the finiteness theorems is plainly satisfiable (for example lcm 2 3 = 6, checked).

## 5. Non-vacuity: my own scratch checks

These are in a scratch file outside the repository; all compile with no errors.
1. `permA 2 1 ≠ 1`: `permA 2 1 0 = -2`, proved from the definitions with exp(−πi) = −1.
2. `GG 2 2 1 1 ≠ ⊥`.
3. `permA 2 1 * permB 2 1 ≠ permB 2 1 * permA 2 1`, i.e. a(b(0)) = 2 ≠ −2 = b(a(0)). So with closed tangent disks the generators do not commute, matching the closed-versus-open remark after [T1] Prop. 7.1, and the group is non-abelian.
4. `{0, 2, -2} ⊆ orbit 2 2 1 1 0`.
5. `orderOf (permA 5 (1/2)) = 5`, and `Nat.card (GG 3 4 (1/2) (1/2)) = 12`, by instantiating `card_GG_of_add_lt_two`.
6. `Nat.lcm 0 4 ∉ S`, `Nat.lcm 2 3 ∈ S`, `Nat.lcm 5 5 ∉ S` and `Nat.lcm 1 5 ∉ S`, where S = {1, 2, 3, 4, 6}.
7. `permA 3 (-1) = 1`: a negative radius gives the identity, as expected and harmless.
8. Direction of rotation: `permA 4 1 0 = -1 - I`, a clockwise quarter turn about −1.

## 7. Issues by severity

**Correctness.** None found.

**Minor, statement or documentation**
1. The docstring of `Statements.card_GG_of_add_lt_two` (and of `Disjoint.lean`) says the group *is* C_{n₁} × C_{n₂}, but the statement gives only the order. Either export the isomorphism `GG n₁ n₂ r₁ r₂ ≃* ZMod n₁ × ZMod n₂` (or `zpowers a × zpowers b`), or reword the docstring to "has order n₁ n₂ (it is the internal direct product of ⟨a⟩ and ⟨b⟩)".
2. The `Statements.lean` header lists `infinite_orbit_radii` as [BC] Corollary 4.2 without saying that it proves r₀ > 0 rather than r* ≥ 1. The weakening should be stated in the docstring or in the implementation notes.
3. The `Statements.lean` header says nothing about the bounds being existential rather than explicit ([T1] Thm 5.1, [BC] Thm 4.1). A short sentence in the implementation notes would make the record exact.
4. The `Statements.lean` module docstring has no blank line before `## Implementation notes`. This is cosmetic, but it may render as part of the preceding list item.

**Informational**
5. Inside Lean, nothing shows that the hypotheses of the boundary-contact theorems are ever satisfied (an infinite orbit). That is expected, because it needs the paper's infinite-orbit results, but it means those three theorems are verified as implications only.

## 9. Mathlib-style notes (brief, no rewrites)

1. Source headers have no `Copyright` line. Mathlib requires one; this project deliberately omits it, following the user's convention.
2. `Group.lean` defines private `apply_inv_apply'` and `inv_apply_apply'`, which restate `Equiv.apply_symm_apply` and `Equiv.symm_apply_apply` for permutations (via `Equiv.Perm.inv_def`; I did not pin down the exact `Perm`-specific simp-lemma names at this Mathlib revision). A reviewer would ask for existing lemmas or `simp` to be used.
3. Some names would draw comment:
   - `I_sq_eq` and `conj_I_eq` are opaque; something like `I_sq_eq_lattice` would say what they are for.
   - `exp_fourth` and `exp_sixth` should name the angle (e.g. `exp_neg_two_pi_I_div_four`).
   - `lattice` is very generic for ℤ + ℤη.
   - The primed `orbit_eq_of_agree'` should get a descriptive suffix (`_of_eq_radii`).
4. Many public theorems have no docstrings: `norm_exp_rotationAngle`, `dist_rotation`, `iterate_rotation`, most lattice lemmas, `diskRotation_eq_or_of_le`, `pos_of_infinite`. Mathlib only requires them for definitions (which all have them), but main results should have them.
5. `MonoidHom.finite_of_fg` and `MulAction.finite_of_encard_orbit_le` sit in Mathlib namespaces in a project file. They are reasonable upstream candidates. Before proposing them, check for an existing Mathlib equivalent (e.g. around `Group.FG` and `Finite (G →* M)`).
6. `TDCSG.Statements` duplicates every declaration name of `TDCSG`. This suits a "statements file" pattern, but Mathlib would not do it. It is fine for this project.
7. `orderOf_diskPerm` ends with `field_simp` / `nlinarith` on an integer equation, which is fragile. `Complex.exp_eq_one_iff` combined with `Int` divisibility would be more robust.
8. Module docstrings, section headers and `## Main statements` lists follow the Mathlib layout well. The references to `notes/proofs/*.md` would not belong upstream.
